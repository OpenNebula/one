      "content": "# PCI Affinity/Antiaffinity Template Extension\n\nAdd the following attributes to the PCI template section of a Virtual Machine to enforce scheduling constraints based on PCI addresses for SR-IOV vNICs.\n\n## Attributes\n\n- **ADDRESS**: PCI address in format `domain:bus:device.function` (e.g., `0000:00:1f.2`).\n- **AFFINITY**: `AFFINITY` (default) to require that all PCI addresses in the same group are on the same host; `ANTI` to require they are on different physical NICs (different PCI addresses).\n- **GROUP** (optional): A string grouping name. If omitted, all PCI entries are considered in one group.\n\n## Example\n\n```\nPCI = [\n  ADDRESS = \"0000:00:1f.2\",\n  AFFINITY = \"ANTI\",\n  GROUP = \"sr-iov\"\n]\nPCI = [\n  ADDRESS = \"0000:00:1f.3\",\n  AFFINITY = \"ANTI\",\n  GROUP = \"sr-iov\"\n]\n```\nThis indicates that the VM requires two vNICs attached to different physical NICs (different PCI addresses). The scheduler will only place the VM on hosts that have at least two distinct PCI devices matching the given addresses.\n\nFor affinity:\n```\nPCI = [\n  ADDRESS = \"0000:00:1f.2\",\n  AFFINITY = \"AFFINITY\",\n  GROUP = \"same\"\n]\nPCI = [\n  ADDRESS = \"0000:00:1f.3\",\n  AFFINITY = \"AFFINITY\",\n  GROUP = \"same\"\n]\n```\nThis requires both PCI devices to be present on the same host.\n\n## Notes\n- The scheduler must be configured to use `PCIAffinityScheduler`.\n- Hosts must report their PCI devices via `PCI_INFO` in their template (comma-separated list of addresses).\n"
